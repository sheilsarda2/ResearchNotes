# Reimplement the rerun_c bridge of the Rerun C++ SDK

Repository: `/workspace/repo` (rerun-io/rerun at version `0.38.0-alpha.1+dev`). The C++ SDK lives in `rerun_cpp/`. It is a thin, hand-written layer on top of two libraries: **rerun_c** (`crates/top/rerun_c`, a Rust static library exposing the C API declared in `rerun_cpp/src/rerun/c/rerun.h`) and **Apache Arrow C++** (used for all serialization). Everything under `rerun_cpp/src/rerun/archetypes/`, `components/`, `encodings/` and `blueprint/` is generated code that only depends on a handful of hand-written building blocks: `rerun::Error`/`rerun::Result`, `rerun::Collection`, `rerun::ComponentBatch`, `rerun::ComponentColumn`, `rerun::TimeColumn` and `rerun::RecordingStream`.

The part of the SDK that talks to rerun_c has been removed from this tree. Every public and private member that the headers under `rerun_cpp/src/rerun/` declare is still declared and documented, but the following declarations have **no definition** anywhere in `rerun_cpp/src`:

As a result `rerun_sdk` (the static library) still compiles, but the `snippets` and `rerun_sdk_tests` executables fail to link. Your job is to implement all of the above so that the SDK works again exactly as the Python and Rust SDKs do.

## Where to work

* Edit and add files only under `rerun_cpp/src/`. That directory is the only thing collected from your container; anything else you change (build files, tests, snippets, `crates/`) is discarded, and `rerun_cpp/tests/`, `rerun_cpp/docs/` and `docs/snippets/` are restored from a pristine copy before verification.
* Do not modify the generated directories (`rerun_cpp/src/rerun/archetypes/`, `components/`, `encodings/`, `blueprint/`, `rerun_cpp/src/rerun/datatypes.hpp`) or the C header directory `rerun_cpp/src/rerun/c/`. They are restored from the pristine copy too, so any change there is silently undone.
* You may add new `.cpp`/`.hpp` files (the CMake build globs `rerun_cpp/src/**/*.cpp|*.hpp`), add private helpers, and change private members of the declared classes. Keep every public signature, default argument and documented behavior as declared in the headers; the tests and the 121 C++ snippets compile against those headers unchanged.
* C++17, GCC 13, no new third-party dependencies. Arrow C++ 18.0.0 headers (`<arrow/...>`) are available to `rerun_sdk` and may be included from `.cpp` files and from headers that already include Arrow; `rerun.hpp` must not leak `c/rerun.h` (an existing header check enforces this).

## Behavioral contract

The authoritative references are: the C API documentation in `rerun_cpp/src/rerun/c/rerun.h` (and its Rust implementation in `crates/top/rerun_c/src/lib.rs`, read-only), the doc comments in the headers listed above, and the Python/Rust snippets that sit next to every C++ snippet under `docs/snippets/all/**` (same file name, `.py`/`.rs`). The C++ output must be semantically identical to the Rust output for every snippet. The following statements are required behavior; hidden checks trace to them.

### Errors (`error.hpp`)
1. `Error(const rr_error&)` copies the code (same numeric values as `rr_error_code`; the `ErrorCode` enum already mirrors them) and the description. `Error(const arrow::Status&)` maps `arrow::StatusCode::OK` to `Ok`, `OutOfMemory` to `OutOfMemory`, every other Arrow status code to the matching `ErrorCode::ArrowStatusCode_*` value (unknown codes to `Unknown`), and carries the Arrow message as description.
2. `handle()`: nothing happens for `Ok`. Otherwise, if a handler was installed with `set_log_handler`, it is called with the error and the user data (and nothing else happens); else if strict mode is on, `throw_on_failure()` (or `abort()` without exceptions); else the description is printed to stderr as `Rerun ERROR: <description>`. Strict mode is on when the environment variable `RERUN_STRICT` is one of `1`, `true`, `yes`, `on` (case-insensitive); `0`, `false`, `no`, `off` and empty mean off; anything else prints a warning and means off. `set_log_handler(nullptr)` restores the default behavior. `exit_on_failure()` calls `handle()` and then `std::exit(1)` for non-`Ok` errors.

### Version check and strings (`sdk_info.hpp`, `string_utils.hpp`)
3. `version_string()` returns rerun_c's `rr_version_string()`. `check_binary_and_header_version_match()` returns `Ok` when it equals `RERUN_SDK_HEADER_VERSION`, else `ErrorCode::SdkVersionMismatch` with a description that includes both versions. Constructing a `RecordingStream` and calling `rerun::spawn` perform this check (the constructor handles the result with `Error::handle`, `spawn` returns it).
4. `detail::to_rr_string` produces a non-owning `rr_string` (`utf8` pointer, `length_in_bytes`); the `std::optional<std::string_view>` overload yields `{nullptr, 0}` for an empty optional. rerun_c strings are never required to be null-terminated.

### Entity paths (`entity_path.hpp`)
5. `escape_entity_path_part` escapes one path part through rerun_c (`_rr_escape_entity_path_part`, freeing the result with `_rr_free_string`); on failure it handles an `InvalidStringArgument` error and returns the input unchanged. `new_entity_path({"world", "42", "my image!"})` returns `"/world/42/my\ image\!"` (each part escaped, joined with a leading `/`); an empty list returns `"/"`.

### Component types, batches and columns
6. `ComponentType::register_component` registers the descriptor (`archetype`, `component`, `component_type`, each passed as an `rr_string`, empty meaning null) together with the Arrow data type exported through the Arrow C Data Interface (`ArrowSchema`), and returns the handle or the rerun_c error (registering a descriptor whose `component` is empty fails with `InvalidStringArgument`, as reported by rerun_c).
7. `ComponentBatch::from_arrow_array(array, descriptor)` produces a batch whose `array` is the given array and whose `component_type` is the handle for that descriptor. A given descriptor is registered with rerun_c at most once per process, no matter how many batches, threads or archetypes use it; later batches reuse the cached handle. `ComponentBatch::length()` is the number of elements in `array`.
8. `ComponentBatch::to_c_ffi_struct` rejects a batch whose `array` is null with `ErrorCode::UnexpectedNullArgument` (nothing is handed to rerun_c in that case) and otherwise fills `component_type` and exports the array through the Arrow C Data Interface, keeping the Arrow data alive until rerun_c releases it. `ComponentColumn::to_c_ffi_struct` behaves the same way for columns.
9. `ComponentColumn::from_batch_with_offsets(batch, offsets)` wraps the batch's array in an Arrow list array of type `list(batch array type)` with the given offsets (`offsets.size() - 1` rows); `from_batch_with_lengths` converts lengths to offsets starting at 0 and delegates. `ComponentBatch::partitioned(lengths)` returns that column; the argument-less `partitioned()` uses unit lengths (one component per row).

### Timelines and time columns (`timeline.hpp`, `time_column.hpp`)
10. `Timeline::to_c_ffi_struct` maps `TimeType::Sequence/Duration/Timestamp` to `RR_TIME_TYPE_SEQUENCE/DURATION/TIMESTAMP` and the name; any other value is `ErrorCode::InvalidEnumValue`.
11. `TimeColumn(timeline, times, sorting_status)` stores the times as a primitive Arrow `int64` array (no nulls) and keeps the sorting status. `from_seconds` converts seconds to nanoseconds with round-to-nearest (`std::llround(secs * 1e9)`) on a `Duration` timeline. `to_c_ffi_struct` fills the timeline, exports the array and maps `SortingStatus::Unknown/Sorted/Unsorted` to `RR_SORTING_STATUS_UNKNOWN/SORTED/UNSORTED` (anything else is `InvalidEnumValue`).

### Sinks and spawn options (`log_sink.hpp`, `spawn_options.hpp`, `spawn.hpp`)
12. `detail::to_rr_log_sink` converts `GrpcSink` (`RR_LOG_SINK_KIND_GRPC`, url), `FileSink` (`RR_LOG_SINK_KIND_FILE`, path) and `GrpcServerSink` (`RR_LOG_SINK_KIND_GRPC_SERVER`: bind ip, port, server memory limit, `newest_first == (playback_behavior == NewestFirst)`). `RecordingStream::try_set_sinks` passes all sinks in one `rr_recording_stream_set_sinks` call; for server sinks the CORS origin strings are passed as an `rr_string` array that stays valid for the duration of the call (`nullptr`/0 when empty). The error code of the call is returned (`RecordingStreamSaveFailure` when the file sink path is a directory, `InvalidServerUrl` for an invalid gRPC url, `Ok` for `rerun+http://127.0.0.1:9876/proxy` even when nothing listens there).
13. `SpawnOptions::fill_rerun_c_struct` copies `port`, `memory_limit`, `server_memory_limit`, `hide_welcome_screen`, `detach_process`, `executable_name` and `executable_path` field by field. `rerun::spawn(options)` runs the version check, then `rr_spawn`.

### RecordingStream lifecycle
14. `RecordingStream(app_id, recording_id, store_kind, send_properties)` creates a rerun_c stream with `rr_recording_stream_new(store info, rerun::is_default_enabled(), send_properties)`. On success `is_enabled()` reflects `rr_recording_stream_is_enabled`; on failure the error is handled (`Error::handle`) and the stream is disabled. An application id that is not valid UTF-8 (for example `"\xc3\x28"`) produces `ErrorCode::InvalidStringArgument` through the log handler and does not crash. `kind()` returns the constructed store kind.
15. The destructor frees the underlying stream (`rr_recording_stream_free`) exactly once; a moved-from stream must not free anything, and the two special handles `RR_REC_STREAM_CURRENT_RECORDING`/`RR_REC_STREAM_CURRENT_BLUEPRINT` are never freed. `set_global`/`set_thread_local` register the stream for its store kind. `current(kind)` returns a reference to a process-wide `RecordingStream` bound to the special handle for that kind; its `kind()` is the requested kind and it reports `is_enabled() == false` while no stream of that kind has been made global or thread-local at the time it is first created. A stream declared `static` at namespace scope must not crash at process exit.
16. Sinks: `connect_grpc(url)`, `save(path)`, `to_stdout()`, `spawn(options)`, `serve_grpc(...)` and `flush_blocking(timeout)` forward to the corresponding `rr_recording_stream_*` functions and return their error. `serve_grpc` returns `"rerun+http://{bind_ip}:{port}/proxy"` on success. After `connect_grpc` to an address without a server, logging still works and `flush_blocking()` returns `ErrorCode::RecordingStreamFlushFailure`; the stream remains usable afterwards. `save` to a path that is an existing directory returns `RecordingStreamSaveFailure`; a successful `save` creates the file immediately.
17. Time: `set_time_sequence`, `set_time_duration_nanos` and `set_time_timestamp_nanos_since_epoch` call `rr_recording_stream_set_time` with `RR_TIME_TYPE_SEQUENCE`, `RR_TIME_TYPE_DURATION` and `RR_TIME_TYPE_TIMESTAMP`; `disable_timeline`, `reset_time`, `set_log_tick_enabled` and `set_log_time_enabled` forward likewise. Errors from these calls are handled with `Error::handle`, never returned; none of them produce an error in normal use, including `disable_timeline` on a timeline that does not exist and setting time again after `reset_time`.

### Logging
18. `try_log_serialized_batches(entity_path, static_, batches)` is a no-op returning `Ok` on a disabled stream; otherwise it logs one data row with `inject_time = !static_`. `try_log_data_row(entity_path, n, batches, inject_time)` converts every batch with `ComponentBatch::to_c_ffi_struct` (a null array fails the whole call with `UnexpectedNullArgument`; an invalid component type handle such as `RR_COMPONENT_TYPE_HANDLE_INVALID` fails with `InvalidComponentTypeHandle`, as reported by rerun_c), then calls `rr_recording_stream_log` once with all batches and returns its status. Errors from `AsComponents`/`Loggable` serialization are propagated unchanged by `try_log`, and reported through the log handler by `log` (the existing templates in `recording_stream.hpp` already do this on top of `try_log_serialized_batches`). Logging an archetype with zero instances or an empty component batch must succeed without error.
19. `try_log_file_from_path` and `try_log_file_from_contents` forward to `rr_recording_stream_log_file_from_path`/`_from_contents` (path as string, contents as `rr_bytes`, entity path prefix, static flag), returning `Ok` immediately on a disabled stream.
20. `try_send_columns(entity_path, time_columns, component_columns)` converts every `TimeColumn` and `ComponentColumn` to its C struct and issues a single `rr_recording_stream_send_columns` call with all time columns and all component columns; any conversion error aborts the call and is returned. Disabled streams return `Ok`.
21. `try_send_recording_name(name)` and `try_send_recording_start_time_nanos(nanos)` set the recording's built-in properties: they log, as static data under the reserved properties entity path (`RecordingStream::PROPERTIES_ENTITY_PATH`), the `RecordingInfo` archetype with only the `name` (respectively `start_time`) field set (`RecordingInfo::update_fields().with_name(...)` / `.with_start_time(...)`), exactly like the Rust and Python `send_recording_name`/`send_recording_start_time` do (see `docs/snippets/all/concepts/recording_properties.*`).

### Cross-language equivalence
22. For every runnable C++ snippet under `docs/snippets/all/**` (the `snippets` executable built from `docs/snippets/CMakeLists.txt`), running it with the environment `RERUN_FLUSH_NUM_ROWS=0 RERUN_STRICT=1 RERUN_PANIC_ON_WARN=1 _RERUN_TEST_FORCE_SAVE=<out.rrd>` from the repository root must exit 0 and write a recording that `rerun rrd compare --unordered --ignore-chunks-without-components` judges equal to the recording written by the Rust version of the same snippet. `docs/snippets/snippets.toml` (`[opt_out.run]`, `[opt_out.compare]`, `[extra_args]`) defines which snippets run and are compared; this is the same rule set as upstream `docs/snippets/compare_snippet_output.py`. With the current tree that is 112 snippets run and 104 compared. `_RERUN_TEST_FORCE_SAVE`, `RERUN_FLUSH_NUM_ROWS`, `RERUN`, `RERUN_LOG_TICK` and `RERUN_LOG_TIME` are interpreted by rerun_c; the C++ layer must not read or special-case them.

## How you are evaluated

The verifier copies your `rerun_cpp/src` over a pristine copy of this tree, restores the generated code, the C header directory, all tests and the snippets, rebuilds `snippets` and `rerun_sdk_tests` with the same CMake configuration as `/workspace/repo/build/debug`, and then requires all of:

1. the build succeeds and links only the prebuilt `rerun_c` and Arrow;
2. `./build/debug/rerun_cpp/tests/rerun_sdk_tests` (Catch2, run with `RERUN_STRICT=1`) reports exactly 45 test cases, all passed;
3. all 112 runnable C++ snippets exit 0 and write a recording;
4. all 104 compared snippets match the Rust reference recording (produced from the same commit) under `rerun rrd compare --unordered --ignore-chunks-without-components`.

The reward is 1 only if all four hold; per-group results are recorded for diagnosis. Snippet binaries are executed as an unprivileged user with the reference recordings unreadable. Submissions whose sources spawn processes, load libraries dynamically, enumerate directories, or mention verifier paths (`/logs`, `/opt/reference`, `_RERUN_TEST_FORCE_SAVE`, `RERUN_FLUSH_NUM_ROWS`, ...) are rejected before building.
