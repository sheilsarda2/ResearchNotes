Add explicit durable state transitions to this Luigi checkout. A dynamic task's run() currently restarts from the beginning when it yields incomplete dependencies. Implement an opt-in `CheckpointTask` that preserves committed JSON state and discovered requirements across worker/process restart. Keep ordinary Task and DynamicRequirements behavior compatible, and integrate with real Luigi workers and their completion cache.

Export from both `luigi` and `luigi.checkpoint`:

* `CheckpointTask`, a Task subclass, and immutable value objects `Transition(state, requires=None)` and `Finish(state)`.
* ValueError subclasses `CheckpointValidationError`, `CheckpointCorruptionError`, `CheckpointVersionError`, `CheckpointIdentityError`.
* RuntimeError subclasses `CheckpointBusyError`, `CheckpointConflictError`, `CheckpointOutputError`.

A subclass overrides `checkpoint_path()` (a local JSON file path/PathLike), `initial_state()`, `advance(state, inputs)`, and normal `output()`. `checkpoint_version` is a nonempty string, default `"1"`. The application changes this version when its state semantics change. checkpoint_path is application chosen: reject an identity collision instead of silently using another task's state.

Protocol:

1. An absent journal is incomplete even if outputs already exist. On execution, call initial_state and durably initialize sequence 0 in phase `ready`. Call advance with a defensive copy of that state and inputs=None. Valid state consists only of JSON null, bool, str, int, finite float, lists and string-keyed dicts; reject nonfinite numbers, tuples/bytes/sets, non-string keys and cycles with CheckpointValidationError. Unsupported initial state must leave no initialized journal.
2. `Transition` commits the new state together with the complete discovered requirement structure, advances the sequence by one and enters `waiting`. Persist before yielding dependencies to the worker. Requirements may contain importable Luigi Tasks, None, lists, tuples, and string-keyed dicts, preserving structure, ordering, repeated task references and None leaves. Reject cycles, unsupported leaves/keys, self-dependencies, non-importable task classes (including __main__ and function-local classes), and parameters that cannot round-trip. Reconstruct tasks from their module, family and all serialized parameters, including insignificant/private parameters, so re-entry does not need to rediscover the graph. Validation failure leaves the last committed transition intact.
3. A waiting transition rechecks every child using current completion, never merely a previously cached true. If children remain incomplete or fail, preserve state and sequence and yield the same requirements again. Child tasks must actually be scheduled by Luigi, not run directly by the checkpoint implementation. When all children complete, call advance with the committed state and a matching nested structure of their output targets. None leaves remain None; empty requirement structures continue without scheduling work. Ignore stale worker-provided outputs and reconstruct/revalidate from the journal.
4. `Finish` commits its state, increments the sequence and enters `finished`, but only when normal output() returns at least one target and every target exists. Otherwise raise CheckpointOutputError without committing Finish. An invalid return type raises CheckpointValidationError. Exceptions from application hooks propagate and do not overwrite the previous journal. A finished journal plus complete outputs makes complete() true; rerunning it does not call hooks again. If finished outputs later disappear, complete() returns false and execution raises CheckpointOutputError until an explicit reset, without rerunning unknown effects.
5. This is a durable-transition guarantee: after a transition commit, a fresh invocation must not re-execute the advance that produced it. A hook interrupted before its journal commit may execute again. Do not claim exactly-once external side effects. Use an atomic `os.replace` of checkpoint_path as the journal publication boundary, and flush file/directory data before reporting commit success. Interruption or an exception just before/after that replacement must leave a valid previous or next journal, never partial JSON or an automatic rollback of an already committed transition.

Journal and administration:

* Persist a UTF-8 JSON envelope with `schema_version: 1`, `data: <object>`, and `sha256: <hex SHA-256 of canonical data>`. Canonical data uses json.dumps(sort_keys=True, separators=(',', ':'), ensure_ascii=False, allow_nan=False) encoded as UTF-8. The data object includes `identity`, `checkpoint_version`, `epoch`, `sequence`, `phase`, `state`, and encoded requirements. The encoded requirements' private representation is your choice. A reset/reinitialization must use a different epoch, so a suspended older generator cannot overwrite a new sequence with the same numeric value.
* Validate schema, checksum, sequence (nonnegative integer, not bool), phase consistency, state, and dependency descriptors on load. Reject malformed/truncated JSON, duplicate JSON keys, unknown schema, invalid or corrupted fields, and corrupted checksums with CheckpointCorruptionError. Never silently start over on corruption. A mismatched checkpoint_version raises CheckpointVersionError, and a mismatched identity raises CheckpointIdentityError. Identity includes task module, family, and every significant serialized parameter; insignificant parameters do not split checkpoint identity. The implementation may restrict journals to regular local files and must not follow a journal or lock-file symlink.
* `checkpoint_status()` returns a defensive dict with keys `phase`, `sequence`, `state`, `checkpoint_version`, `identity`, `pending_task_ids`. Absent status is phase `absent`, sequence 0, state None, and no pending IDs. Pending IDs are unique, preserving first traversal order. Status and complete() must not create an absent journal or parent directory. Corruption/version/identity errors propagate from these methods. Unrelated permissions and I/O failures also propagate instead of being treated as absence.
* `reset_checkpoint(expected_sequence)` atomically removes a valid matching journal only if its current sequence equals the supplied nonnegative integer (not bool). It returns True if removed and False when already absent with expected_sequence=0. A different sequence raises CheckpointConflictError. Reset accepts a valid same-identity journal from an older checkpoint_version, allowing an explicit upgrade. It rejects malformed journals and identity collisions; an administrator can separately archive/remove corrupted files while all workers are stopped. Reset does not delete task outputs.

Concurrency and integration:

* Serialize initialization, advance hooks, journal commit and reset using a per-journal POSIX interprocess lock. A competing operation must promptly raise CheckpointBusyError rather than execute another hook or block indefinitely. The lock is released on exception and process death.
* Release the execution lock while yielding/waiting for child tasks. A suspended generator carries a receipt identifying its journal epoch and sequence. On continuation after another invocation or reset changes that state, raise CheckpointConflictError before invoking another hook. Closing a suspended generator must not leave a lock held. A newly invoked task can resume the waiting state normally.
* Use Luigi's real dynamic dependency mechanism and preserve nested target inputs. Both ordinary nested dependency yields and DynamicRequirements wrappers are valid; no specific wrapper class is required. Invalidate or bypass stale completion-cache entries for checkpoint requirements so a deleted child output is scheduled again; preserve caching semantics for ordinary dynamic tasks. Tests exercise one and multiple workers, failed/deleted children, fresh interpreter reconstruction, process termination, competing advance/reset operations and stale suspended continuations.

Document the new API and its replay limits. Scope is local POSIX filesystems with a single host's interprocess locking. No arbitrary Python frame/generator pickling, remote service, distributed scheduler, network filesystem guarantees, or external-side-effect transaction protocol is requested. Do not modify verifier infrastructure or install a substitute package.

Evaluation uses a fresh offline container with the pinned dependencies. Only `/workspace/repo/luigi/` is transferred as the submitted implementation. Keep runtime feature code inside that package; upstream tests and documentation may also be edited for development but do not replace the independent verifier.
