# Confirmation image identity and independent validation

The single normal oracle confirmation uses the exact frozen final task and unchanged resources. Docker assigned its verifier image a different metadata ID from the first control's image. The old checksum-scoped private tag deliberately refuses to change images, so the frozen controller's image-pinning callback reports an assertion while the actual trial continues. The original controller, callback errors, old image tag and original failed oracle remain unchanged.

`capture.json` binds the actual confirmation container to its unique private tag, full verifier test-file map, filtered Docker inspection and normal resource settings. The old and new image IDs have exactly the same 19 root filesystem layer hashes. This proves filesystem identity in addition to the direct test-file comparison; it does not make the two metadata IDs interchangeable in provenance.

`validate_existing_oracle.py` is a separately tested post-completion validator. It can emit `../oracle-independent-validation-001` only after the existing controller exits, the same raw normal oracle has reward 1 and passes every required group/count, all source and task hashes match, and complete sampled plus fresh locked terminal admission/cleanup evidence is available. Only the exact nonterminal private-tag collision callback error is accepted. Unknown errors, any test failure, a missing fresh terminal sample, or a changed image/test map stop validation. It never launches a solver, repeats an oracle or rewrites existing results.

The capture and independent oracle certificate are complete. The normal oracle raw result is reward 1; the unchanged timing test passed its existing individual retry after an initial failure. `../oracle-independent-validation-001/summary.json` binds the full result and cleanup. `../controls-confirmed-001/summary.json` selects it explicitly as independent validation of the same physical control, with the original failed controller summary retained.
