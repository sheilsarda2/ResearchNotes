# Construction and validation

The task uses current sqlite-utils main `85b1be10c81d9dd3567e36faf8dd411e4a8789bd`, rechecked using `git ls-remote` on September 13, 2026. Its clean archive is byte-identical to the archive used by the two completed sqlite-utils candidates. It includes the Apache license and original source/tests, and excludes the new feature, reference patch and hidden verifier.

Public overlap is substantial and disclosed in provenance: native SQLite ALTER already rewrites column dependencies; PR703 provides an incoming-FK transformation solution; PR499 addresses FTS trigger recreation; PR854 only documents existing trigger loss and view limitations. The task asks for a coordinated type/default/nullability/order rebuild with native renames and safe drops, not a rename fix. The reference reuses the repository's lexer for lossless column-definition span edits and uses native SQLite for view/trigger/index/FK renaming. It preserves clauses such as collations, named conflict policies and FK deferrability that the existing transform renderer does not retain completely.

The new suite has 119 behavioral cases; 213 protected upstream cases exercise existing atomic, transform, table-parser and foreign-key behavior. They are verbatim copies from the pinned source with its fixture. Hypothesis is pinned and seeded. Both offline runs collected 332 cases without skips or expected failures. Oracle: 332 passed, reward 1. Untouched baseline: 119 failed, 213 passed, reward 0. Full diagnostics and JUnit XML are retained for both runs.

Validation included a real subprocess exiting between table rebuilds, followed by database reopening and hot-journal recovery; a competing BEGIN IMMEDIATE writer; read-only WAL snapshot dry-run and byte comparison; graph/cyclic/composite FKs; preserved deferrability and cascade behavior; trigger effects after ordinary subsequent writes; expression/partial indexes; unchanged hidden rowids and deleted AUTOINCREMENT high-water marks; loss-preventing ON CONFLICT conversion failures; and default strings with SQL-looking contents and embedded NUL.

The reference temporarily disables FK enforcement outside its own transaction so dropping old tables cannot cascade. It takes BEGIN IMMEDIATE before schema inspection, validates foreign keys before and after, retains incoming FK SQL during internal renames, recreates dependencies after all copies, and restores foreign_keys/defer_foreign_keys/legacy_alter_table entry settings. Calls inside caller transactions are explicitly rejected without touching their work. Dry run executes the same operation on a backup snapshot, including data validation.

Declared boundaries: main-schema ordinary rowid tables and built-in functions/collations; no selected virtual/generated/WITHOUT ROWID tables, PK type/nullability changes or all-rowid-alias shadowing; TEMP and attached objects are outside the contract. Unrelated virtual tables are exercised and remain usable. The reference keeps converted table rows and preview backups in memory; the task makes no unbounded-scale memory promise.

Python 3.12.11, SQLite 3.40.1, aarch64; Docker verifier networking disabled, 2 CPUs and 4096 MB. Root owns separate-verifier Harbor packaging and validation. No paid/model trial or agent-step measurement was performed. Original take-home files still match commit c1ae968.
