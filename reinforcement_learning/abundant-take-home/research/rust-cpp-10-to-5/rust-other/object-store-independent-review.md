# Independent task review: object_store full-range HTTP responses

Reviewed September 13, 2026 by the coordinating agent, separately from the task author. Read the instruction, reference diff, protected HTTP fixture, verifier runner, source pin and construction results. No task files were changed for this review.

No blocker found. The reference stays inside the HTTP adapter and uses the existing `GetRange::as_range` rules. It admits a 200 only when the requested range resolves to the complete nonempty representation. Replacing the internal Content-Range in that case keeps the existing metadata and retry machinery in use; a stray header cannot authorize an ignored proper subrange. The instruction permits other implementations and does not require this normalization strategy.

The independent tests observe public APIs and actual loopback HTTP, including exact bytes, size, offsets, ETag and attributes. They cover accepted bounded, clamped, offset and suffix requests; preserved 206 and ordinary GET/HEAD behavior; and incomplete bodies. Retry tests acknowledge receipt of the first body frame before the server closes, avoiding a sleep-based race. The two important retry boundaries are tested: zero bytes consumed can still accept a whole-object 200, while a consumed prefix must resume correctly without duplication or a changed ETag. Protected upstream range tests give a separate compatibility control.

The verifier forces a rebuild of object_store after source transfer, restores its independent integration target and requires both exact positive test summaries. The isolated container supplies manifests, lockfile and tests. Direct Linux evidence shows baseline 0 with six intended feature failures and reference 1 with 14 passing checks. The broader library's root-only permission-test failure is explained and reproduced successfully with the same binary under an unprivileged UID; it is not hidden or part of the grading set.

Limits: the HTTP fixture does not run Polars or miniserve themselves. Header/body semantics and the actual object_store API reproduce the reported boundary. Invalid/empty ranges and a 200 lacking a usable full length retain existing behavior and are outside the added acceptance contract. The compact natural fix does not establish model headroom or a long agent horizon. Final Harbor source-transfer validation remains a separate coordinator check.
