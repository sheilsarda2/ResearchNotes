# Proposed opt-in streaming integration for a new attempt

Status: design only. No runtime implementation, activation, new model request, or task launch is authorized by this document. Existing in-flight attempts and captured runtime files remain unchanged.

## Evidence established

The single real-route probe sent two requests through the configured take-home Anthropic route, Fable5-1/max/adaptive/64000, with no retry or tool execution. Both HTTP200 streams ended with explicit message_stop; the process finished in 8.943 seconds. An 812-byte signature attached to an empty thinking block survived provider→Mini→the second serialized request with identical hashes and API acceptance. Nonempty signed thinking text was covered only by synthetic fixtures. Provider usage was 1,172 input and 171 output tokens, with zero cache tokens. Mini recorded 0.0, which is not evidence of a free provider request; actual charge is unknown. The short exchange does not establish relief from approximately 291-second gateway failures, long-lived heartbeats, or benchmark cancellation.

## Additive entry point

Mini2.4.6 already accepts `--model-class` and `model.model_class` (captured `run/mini.py:55–100`, `models/__init__.py:43–62`). A new private model subclass can inherit `LitellmModel` and change only synchronous `_query`: require the reviewed LiteLLM source identity, apply the checked iterator/complete-thinking context, call the inherited implementation with explicit `stream=true` and `complete_response=true`, and return only after final completion/usage. Keep the inherited message preparation, action parsing, trajectory serialization, retry policy, registry/cost handling, model name, effort, adaptive thinking, max_tokens, cache behavior and existing request timeouts. Store the two streaming flags in the effective model configuration, and record the subclass identity. Do not carry over the probe's retry-off, 90-second idle timeout, socket restrictions, forced tool prompt, synthetic observation or ignore-errors cost configuration.

A separate launcher can load a frozen copy of the existing resource runner, install its usual runtime, then install an additional process-local outer `MiniSweAgent.run` wrapper before invoking its unchanged main routine. The existing chain is `harbor-resource-runner.py:138–144`→tool runtime→base Python/task-file hook→private b.py→installed Mini console script. The new wrapper intercepts exactly the final private b.py launch, after the existing tool preflight. It uploads separately named streaming bootstrap/model/adapter files alongside b.py/c.py and performs a separate no-model preflight. It then invokes the new bootstrap, which registers the supported model class and runs the unchanged b.py console-entry path with the original argv plus the explicit model-class selection. This composition needs a test of actual wrapper ordering; source inspection alone does not prove interception correctness.

Require one launch, exact original task/config hashes, unchanged b.py/c.py bytes, Python3.12.11, Mini2.4.6 and reviewed LiteLLM1.100.1 source hashes. Fail before any provider request on drift, unsupported CLI shape, unexpected model class/settings or a failed preflight. Use no PYTHONPATH/sitecustomize change, installed-package edit, shell/profile change, or inherited task-process patch. The existing neutral private directory provides the model import location. A new sidecar should bind this transport version, all uploaded hashes, original delivered prompt/config, effective flags, interpreter/packages, request-completion accounting and sanitized failures. Keep ordinary full Mini trajectories in their original form; the sidecar need not duplicate thinking/signatures.
