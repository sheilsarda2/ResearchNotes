# Media for the RoFacto review

The result videos and method overview come from Byungjun Kim, Taeksoo Kim, Hyunsoo Cha, and Hanbyul Joo's [official RoFacto release](https://bjkim95.github.io/rofacto/), accompanying [*Robot-Factored World Models via Robot Rendering*](https://arxiv.org/abs/2607.22535v1). Retrieved September 10, 2026.

The `hand-mesh-trajectory` example comes from Byungjun Kim, Taeksoo Kim, Junyoung Lee, and Hanbyul Joo's [*Dexterous World Models* (DWM)](https://arxiv.org/abs/2512.17907), via its [official project](https://snuvclab.github.io/dwm/). It illustrates cited prior work, not a RoFacto result. The triplet shows a recorded interaction, the static scene, and rendered hand meshes used in DWM's training data. It does not show generated predictions. The source's original panel headings remain visible. Retrieved September 10, 2026.

The Markdown editions show animated GIF previews linked to the original videos. The HTML reading editions play labeled local MP4 copies with pause, seek, and fullscreen controls. The copies retain every decoded source frame at the original frame rate and playback speed. The builder counts decoded frames instead of using the reported container duration, which can exclude the final frame's display interval. Presentation changes consist of resizing and labels placed outside the original imagery. The GIF previews sample at 8 fps. No image region has been removed or retouched.

For the two motion-gap comparisons, we placed the authors' separate clips side by side with synchronized starts. These are colored robot outlines over observed footage, not videos generated by three competing models. The observed background provides a visual reference; it is not a privileged future-video condition supplied to RoFacto.

The unmodified [method overview](https://bjkim95.github.io/rofacto/static/image/overview.png) is the authors' figure. `conditioning-streams.png` crops and rearranges its four conditioning columns, with new explanatory labels. It shows the authors' simulated moving-camera example, not DROID. Pixel crop coordinates and layout are recorded in `build_streams_figure.py`; run that script to regenerate the detail. Time runs down each column, and depth is colorized.

The `conditioning-mask.svg`, `denoising-loop.svg`, and `downsampling.svg` files are explanatory diagrams created for this review from its existing answers; they are labeled accordingly. They are not additional experiments or figures from the authors.

The [source manifest](sources.json) records source URLs, durations, frame rates, transformations, and source/output hashes. Rebuilt entries also record decoded frame counts and the source-reported durations separately. Per-item authorship and project fields identify DWM's separate provenance; the top-level authorship describes RoFacto. These selected examples illustrate the text; the paper's aggregate results remain the quantitative evidence.

## Rebuilding the reading editions

After editing either Markdown document, run:

```sh
python3 robotics_ai/media/rofacto/render_reading.py
```

The renderer uses Python `markdown-it-py` and Matplotlib, embeds equations and the existing flowchart as SVG, and prefers the local labeled MP4s. No external JavaScript, fonts, or math service is required for reading or playback.

To regenerate the labeled video assets from the original release, use Python with Pillow, `ffmpeg`, and `ffprobe`:

```sh
python3 robotics_ai/media/rofacto/build_media.py --cache /tmp/rofacto-media
```

To rebuild only selected assets while preserving all other manifest entries and metadata:

```sh
python3 robotics_ai/media/rofacto/build_media.py --cache tmp/rofacto-review/media/raw --only human-retargeting hand-mesh-trajectory
```
